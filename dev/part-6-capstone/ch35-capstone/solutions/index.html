    Chapter 35 – Solutions¶

    Solutions of the Lab and the Exercises of Chapter 35 that have one; the projects and the operator brief are team work and have no single answer, but the Lab below is the baseline every team starts from. The code is in the chapter's src folder. Four programs read ToOp's output files and run anywhere: res_table.py, switching_distances.py, brief.py and hvdc_sensitivity.py. Three need ToOp's interpreter: baseline_toop.py (the staged pipeline, three runs), ac_check_toop.py and sld_toop.py; test_ac_check_toop.py holds the two-line reproduction of Exercise 2. The files under src/baseline/ (res.json, the two configurations, unsplit_ac_metrics.json, and ac_metrics.json plus orao_summary.json per validated topology) are what baseline_toop.py wrote with ToOp ba1874e in the course's ToOp container (image toop-course:cpu, docker run --cpus 4, the work folders in the named volume toop-course-runs): the node-breaker example grid three times with seed 1 and 10 s of runtime (python baseline_toop.py <work> <grid.xiidm> 3 10), and the complex example grid (data/complex_grid/grid.xiidm, an HVDC link; its preprocessing log reports 67 branches, 9 relevant substations and 121 actions) once with 25 s (... 1 25), because the node-breaker grid has one relevant substation and ten actions and cannot show more than two repertoire cells. An earlier run of the same script on the maintainer's Windows host, with the shims below, gave the same DC and AC figures; only the number of epochs differed. Every number below comes from these files or from the programs (python <name>.py; the _toop ones in the container).

    Two Windows notes carried over from Chapter 34: the colons in ToOp's TensorBoard folder names (baseline_toop.windows_shim) and the zero time step between fast epochs (iterations_per_epoch=500); both are harmless in the container. Two more came up here: PreprocessParameters(preprocess_bb_outages=True) fails on a bus-breaker model such as data/case57_xiidm/grid.xiidm (convert_rel_bb_outage_data meets rel_bb_outage_zero_flow_br_indices = None), and the importer's default area settings leave that case57 file with no branches at all, so the capstone's richer grid is the complex example grid.

      The three runs end with the same best topology (action 5, DC overload energy 42.345 MW against 61.445 MW unsplit) but with 39, 55 and 55 epochs: a fixed seed makes the random stream reproducible, a fixed wall-clock budget does not make the amount of work reproducible, which is why Chapter 26 asks for budgets in evaluations.     2. Trace. Action 5 of action_set.json is the fifth local_actions entry: a split of the station VLevel2 (voltage level VL2) that moves line L12 to the second busbar, realized by opening the coupler VL2_BREAKER, opening the disconnector L12_DISCONNECTOR_4_0 and closing L12_DISCONNECTOR_4_2 (the orao_summary.json of topology 0; disconnections is empty). In the DC stage the genotype of a candidate is a vector of action indices per relevant substation (optimizer/dc/genetic_functions/genotype.py, mutated in mutation/); for a batch of candidates compute_symmetric_batch (dc_solver/jax/compute_batch.py) calls compute_bsdf_lodf_static_flows, which applies the BSDF update of the PTDF for each split (bsdf.py), the MODF update for the disconnections (multi_outages.py), then the LODF N-1 flows; aggregate_results.py turns the N-1 matrix into overload_energy_n_1 (42.345 MW), max_flow_n_1 (2.207), split_subs (1), switching_distance (2: the precomputed reassignment_distance of action 5) and top_k_overloads_n_1 (67.27 MW with n_worst_contingencies = 2). The repertoire (optimizer/dc/repertoire/discrete_me_repertoire.py) has one cell per value of the descriptor split_subs; the candidate lands in cell 1, beats whatever was there, and best_topos lists the best of every non-empty cell, here just this one, since the unsplit grid is the initial topology and not a repertoire member. The AC worker's select_strategy (optimizer/ac/select_strategy.py) filters the DC pushes stored in its database with the median, dominator and discriminator masks over the target metrics, and compute_metrics_single_timestep (optimizer/ac/scoring_functions.py) scores the realized topology from the AC N-1 results (fitness = overload_energy_n_1 = 25.377). res_table.weighted_sum_check confirms the DC fitness: target_metrics = {overload_energy_n_1: 1.0}, so fitness = −1.0 × 42.3453 = −42.3453, and the check holds for every row of every baseline file.

    res_table.py
    """Read a ToOp ``res.json``: the ``best_topos`` table, the fitness check and the operator's pick (Chapter 35, Ex. 1).

The files under ``baseline/`` were written by ``baseline_toop.py`` with ToOp ``ba1874e`` (node-breaker grid, three
runs with the same seed; the complex example grid, one run); ``python res_table.py [res.json]`` prints the tables.
"""

import json
import sys
from pathlib import Path

import pandas as pd

BASELINE = Path(__file__).resolve().parent / 'baseline'
NODE_BREAKER = BASELINE / 'node_breaker' / 'run_0' / 'res.json'
COMPLEX = BASELINE / 'complex_grid' / 'run_0' / 'res.json'


def load_res(path):
    """The parsed ``res.json``."""
    return json.loads(Path(path).read_text(encoding='utf-8'))


def best_topos_table(res):
    """One row per entry of ``best_topos``: actions, disconnections, fitness and every ``extra_scores`` metric."""
    rows = []
    for topo in res['best_topos']:
        row = {
            'actions': topo['actions'],
            'disconnections': topo['disconnections'],
            'fitness': topo['metrics']['fitness'],
            **topo['metrics']['extra_scores'],
            'worst_k_contingency_cases': topo['metrics'].get('worst_k_contingency_cases'),
        }
        rows.append(row)
    return pd.DataFrame(rows)


def target_metrics(res):
    """``{metric: weight}`` of the run, from ``args.ga_config.target_metrics``."""
    return {metric: float(weight) for metric, weight in res['args']['ga_config']['target_metrics']}


def weighted_sum_check(res, atol=1e-9):
    """Recompute ``fitness`` as minus the weighted sum of the target metrics and compare it row by row."""
    table = best_topos_table(res)
    weights = target_metrics(res)
    table['recomputed'] = [-sum(w * row[m] for m, w in weights.items()) for _, row in table.iterrows()]
    table['matches'] = (table['fitness'] - table['recomputed']).abs() < atol
    return table


def for_operator(table, max_splits=1):
    """The best (largest fitness) topology with at most ``max_splits`` split substations, or None."""
    eligible = table[table['split_subs'] <= max_splits]
    return None if eligible.empty else eligible.sort_values('fitness', ascending=False).iloc[0]


def main():
    """Print the table, the check and the operator's pick for the file given (default: both baselines)."""
    paths = [Path(sys.argv[1])] if len(sys.argv) > 1 else [NODE_BREAKER, COMPLEX]
    pd.set_option('display.width', 200)
    for path in paths:
        res = load_res(path)
        table = weighted_sum_check(res)
        print(
            f'{path.parent.parent.name}/{path.parent.name}: target metrics {target_metrics(res)}, '
            f'initial fitness {res["initial_fitness"]:.3f}, {len(table)} best_topos'
        )
        print(table.drop(columns=['worst_k_contingency_cases']).to_string(index=False))
        print('fitness equals the negated weighted sum in every row:', bool(table['matches'].all()))
        pick = for_operator(table, 1)
        print(
            'at most one split substation ->',
            None if pick is None else f'actions {pick["actions"]}, fitness {pick["fitness"]:.3f}',
        )
        print()


if __name__ == '__main__':
    main()

    Exercise 2¶

    The two-line reproduction (test_metrics_keyword_is_silently_dropped_in_two_lines in test_ac_check_toop.py):

    metrics = Metrics(fitness=0.0, extra_scores={}, worst_k_contingent_cases=['L8'])
assert metrics.worst_k_contingency_cases is None

    Metrics (optimizer/interfaces/messages/results.py) keeps Pydantic's default extra='ignore', so the misspelled keyword that compute_metrics_single_timestep passes (optimizer/ac/scoring_functions.py: metrics.pop("worst_k_contingent_cases", None) and Metrics(..., worst_k_contingent_cases=...)) is accepted and discarded, and every AC Metrics leaves the worker with worst_k_contingency_cases = None; downstream, get_early_stopping_contingency_ids sees an empty list and logs "No overload threshold or case ids found", so the AC early stopping never gets the DC worst cases. The failing test is the second one in the same file, written against ToOp's own API so that it can move into packages/topology_optimizer_pkg/tests/: run the AC load flow of a topology through create_loadflow_runner, call compute_metrics_single_timestep, assert worst_k_contingency_cases is not None. It fails on ba1874e (marked xfail(strict=True) here) and passes once the keyword is spelled worst_k_contingency_cases on both the pop and the constructor. Pull request, as .github/workflows/validate_pr_title.yaml (commitizen's conventional commits) accepts it:

    Title: fix: pass worst_k_contingency_cases to Metrics in the AC scoring

    Body: compute_metrics_single_timestep builds Metrics with the keyword worst_k_contingent_cases, which the model does not declare; Pydantic ignores it, so the AC metrics never carry the worst contingencies and the early-stopping subset falls back to the full N-1 list (get_early_stopping_contingency_ids logs a warning on every topology). This renames the keyword in the pop and in the constructor, adds test_ac_metrics_carry_worst_contingencies (fails before, passes after), and sets extra="forbid" on Metrics so that the next misspelling is a ValidationError. Fixes #. Signed-off-by: .

    The commit is signed off (git commit -s, the DCO check), the branch comes from a fork, and the hooks run on the host (pre-commit install); the extra="forbid" line is the part a reviewer may push back on, because other producers of Metrics may rely on the leniency, which is exactly the discussion the pull request should start.

    Exercise 3¶

    sld_toop.diagrams and brief.switching_steps on topology 0 of the node-breaker baseline (the station VL2): the before and after diagrams are rendered from grid.xiidm and topology_0/modified_network.xiidm after an AC load flow, with highlight_grid_model_ids set to the three switch ids of orao_summary.json, which the custom style paints in #0050fcff (3 highlighted elements in each SVG, one per switch, counted by their highlight class). Read side by side, the before diagram shows the two busbars of VL2 coupled through the closed VL2_BREAKER, with line L12 on the first busbar (L12_DISCONNECTOR_4_0 closed, _4_2 open); the after diagram shows the coupler open and L12 on the second busbar. The switching steps in operator language:

    1. Open the busbar coupler breaker VL2_BREAKER (a breaker: it can interrupt load current; afterwards the two busbars of VL2 run separately, with the feeders as they are).
    2. Open the disconnector L12_DISCONNECTOR_4_0 to take line L12 off busbar 1 (a disconnector: it must not carry current, so L12 has to be de-energised or its breaker open at this moment; ToOp's switch list says nothing about the line breaker, which is the first thing the operator adds).
    3. Close the disconnector L12_DISCONNECTOR_4_2 to connect L12 to busbar 2 (again without current; then re-close the line breaker, and if L12 was kept live from the far end, synchro-check: the two ends are the same synchronous grid, the angle difference is the one across the open path, small here, 1.8° at most in N-1).

    ToOp's ORAO summary gives the end state of the switches, not an operable sequence: the order above (coupler first, disconnectors with the feeder dead) is the operator's, and the orao_summary.json of ba1874e emits only SWITCH entries (no TERMINALS_CONNECTION, no PST setpoints), as the chapter's discrepancy list notes. For the complex grid the same program produces one pair of diagrams per split station (VL_2W_MV_HV_MV, VL_MV, VL_3W_HV for the three-split topology, 52 000 to 60 000 characters each).

    sld_toop.py
    """Before/after single-line diagrams of a split station with the operated switches highlighted (Ch. 35, Lab 4, Ex. 3).

``diagrams(grid_xiidm, modified_xiidm, orao_summary)`` finds the voltage level of the switches named in the ORAO
summary and renders both networks with ``get_single_line_diagram_custom(..., highlight_grid_model_ids=...)``.
Run with ToOp's interpreter: ``python sld_toop.py <run folder> <data folder> [output folder]`` writes the two SVG
files and prints what they contain.
"""

import json
import re
import sys
from pathlib import Path

import pypowsybl as pp
from toop_engine_grid_helpers.powsybl.single_line_diagram.get_single_line_diagram_custom import (
    get_single_line_diagram_custom,
)


def operated_switches(orao_summary):
    """``[(switch id, open?), ...]`` in the order of the summary."""
    actions = orao_summary['forced-actions']['preventive-actions-list']['actions']
    return [(a['switchId'], a['open']) for a in actions if a['type'] == 'SWITCH']


def stations_of(net, switch_ids):
    """The voltage levels that hold the switches, one per split station, in sorted order."""
    switches = net.get_switches()
    return sorted({switches.loc[s, 'voltage_level_id'] for s in switch_ids if s in switches.index})


def highlighted(svg):
    """How many SVG elements carry the ``highlight`` class that ToOp adds to the highlighted ids.

    The colour ``#0050fcff`` itself appears only in the diagram's CSS, once per voltage class, so counting it says
    nothing about which elements are highlighted.
    """
    return len(re.findall(r'class="[^"]*\bhighlight\b', svg))


def diagrams(grid_xiidm, modified_xiidm, orao_summary, style='bright_mode'):
    """``({level: (before svg, after svg)}, switch states before, switch states after)`` for the split stations."""
    ids = [s for s, _ in operated_switches(orao_summary)]
    before, after = pp.network.load(str(grid_xiidm)), pp.network.load(str(modified_xiidm))
    pp.loadflow.run_ac(before)
    pp.loadflow.run_ac(after)
    svgs = {}
    for level in stations_of(before, ids):
        svg_before = get_single_line_diagram_custom(before, level, custom_style=style, highlight_grid_model_ids=ids)
        svg_after = get_single_line_diagram_custom(after, level, custom_style=style, highlight_grid_model_ids=ids)
        svgs[level] = (svg_before._content, svg_after._content)
    states = lambda net: {s: bool(net.get_switches().loc[s, 'open']) for s in ids}  # noqa: E731
    return svgs, states(before), states(after)


def main():
    """Render the diagrams of every validated topology of a run and report sizes and switch states."""
    run_dir, data_folder = Path(sys.argv[1]), Path(sys.argv[2])
    out_dir = Path(sys.argv[3]) if len(sys.argv) > 3 else run_dir / 'brief_sld'
    out_dir.mkdir(parents=True, exist_ok=True)
    for path in sorted(run_dir.glob('topology_*/orao_summary.json')):
        summary = json.loads(path.read_text(encoding='utf-8'))
        svgs, open_before, open_after = diagrams(
            data_folder / 'grid.xiidm', path.parent / 'modified_network.xiidm', summary
        )
        for level, (before, after) in svgs.items():
            (out_dir / f'{path.parent.name}_{level}_before.svg').write_text(before, encoding='utf-8')
            (out_dir / f'{path.parent.name}_{level}_after.svg').write_text(after, encoding='utf-8')
            print(
                f'{path.parent.name}: station {level}, {len(before)} and {len(after)} characters of SVG, '
                f'{highlighted(before)} and {highlighted(after)} highlighted elements'
            )
        for switch_id, _ in operated_switches(summary):
            print(f'  {switch_id}: open {open_before[switch_id]} -> {open_after[switch_id]}')
    print(f'written to {out_dir}')


if __name__ == '__main__':
    main()
    brief.py
    """A first operator brief from the files a ToOp run leaves behind (Chapter 35, Lab step 4 and Exercise 3).

``situation`` reads ``unsplit_ac_metrics.json``, ``proposals`` the ``topology_*/ac_metrics.json`` files and
``switching_steps`` turns ``orao_summary.json`` into ordered operations in operator language, with a feasibility
note per step (breakers switch under load, disconnectors do not). ``python brief.py [run folder]`` prints the brief
of the node-breaker baseline.
"""

import json
import sys
from pathlib import Path

BASELINE = Path(__file__).resolve().parent / 'baseline'
NODE_BREAKER_RUN = BASELINE / 'node_breaker' / 'run_0'


def load(path):
    """A JSON file."""
    return json.loads(Path(path).read_text(encoding='utf-8'))


def situation(unsplit_ac_metrics):
    """Base case and worst N-1 figures of the grid before any action, from the unsplit AC metrics."""
    s = unsplit_ac_metrics['extra_scores']
    return {
        'worst N-0 loading': s['max_flow_n_0'],
        'worst N-1 loading': s['max_flow_n_1'],
        'N-1 overload energy (MW)': s['overload_energy_n_1'],
        'critical branches N-1': s['critical_branch_count_n_1'],
        'non-converging contingencies': s['non_converging_loadflows'],
        'DC fitness of the unsplit grid': unsplit_ac_metrics['dc_info']['fitness'],
    }


def proposals(run_dir):
    """One entry per validated topology with the figures the brief quotes."""
    out = []
    for path in sorted(Path(run_dir).glob('topology_*/ac_metrics.json')):
        ac = load(path)
        s = ac['extra_scores']
        out.append(
            {
                'topology': path.parent.name,
                'actions': ac['dc_info']['actions'],
                'disconnections': ac['dc_info']['disconnections'],
                'split substations': s['split_subs'],
                'DC overload energy removed (MW)': None,
                'AC N-1 overload energy (MW)': s['overload_energy_n_1'],
                'AC critical branches N-1': s['critical_branch_count_n_1'],
                'non-converging contingencies': s['non_converging_loadflows'],
                'largest voltage-angle difference N-1 (deg)': s['max_va_diff_n_1'],
                'critical voltage-angle differences': s['critical_va_diff_count_n_1'],
            }
        )
    return out


def switch_kind(switch_id):
    """Breaker or disconnector, read from ToOp's switch ids (``*_BREAKER*``, ``*_DISCONNECTOR_*``)."""
    upper = switch_id.upper()
    if 'BREAKER' in upper:
        return 'breaker'
    if 'DISCONNECTOR' in upper:
        return 'disconnector'
    return 'switch'


def switching_steps(orao_summary):
    """Ordered operations of an ORAO summary as sentences with a feasibility note each."""
    actions = orao_summary['forced-actions']['preventive-actions-list']['actions']
    steps = []
    for n, action in enumerate(actions, 1):
        if action['type'] != 'SWITCH':
            steps.append(f'{n}. {action["type"]} {action.get("id", "")}: not a switch operation, check by hand')
            continue
        verb = 'Open' if action['open'] else 'Close'
        kind = switch_kind(action['switchId'])
        if kind == 'disconnector':
            note = 'disconnector: no load current allowed, the breaker in series must be open first'
        elif verb == 'Close':
            note = 'breaker: closing joins two busbars, synchro-check and a small angle difference required'
        else:
            note = 'breaker: can interrupt load current'
        steps.append(f'{n}. {verb} {kind} {action["switchId"]} ({note})')
    return steps


def brief(run_dir=NODE_BREAKER_RUN):
    """The brief as Markdown text: situation, proposals, switching steps, assumptions."""
    run_dir = Path(run_dir)
    lines = ['# Operator brief (draft)', '', '## Situation (unsplit grid, AC N-1)']
    lines += [f'- {k}: {v}' for k, v in situation(load(run_dir / 'unsplit_ac_metrics.json')).items()]
    unsplit_energy = load(run_dir / 'unsplit_ac_metrics.json')['extra_scores']['overload_energy_n_1']
    for prop in proposals(run_dir):
        lines += [
            '',
            f'## Proposal {prop["topology"]}: actions {prop["actions"]}, disconnections {prop["disconnections"]}',
        ]
        prop['DC overload energy removed (MW)'] = None
        lines += [
            f'- {k}: {v}'
            for k, v in prop.items()
            if k not in ('topology', 'actions', 'disconnections') and v is not None
        ]
        ratio = prop['AC N-1 overload energy (MW)'] / unsplit_energy
        lines.append(f'- AC N-1 overload energy relative to the unsplit grid: {ratio:.2f}')
        lines += ['', '### Switching steps']
        lines += switching_steps(load(run_dir / prop['topology'] / 'orao_summary.json'))
    lines += [
        '',
        '## Assumptions and risks',
        "- DC optimization, AC validation with ToOp's N-1 definition; contingencies outside it are not studied.",
        '- Load flow convergence failures are counted, not explained.',
        '- Diagrams: before/after single-line diagrams of the split station with the switches above highlighted.',
    ]
    return '\n'.join(lines)


def main():
    """Print the brief of the run folder given (default: the node-breaker baseline, run 0)."""
    print(brief(Path(sys.argv[1]) if len(sys.argv) > 1 else NODE_BREAKER_RUN))


if __name__ == '__main__':
    main()

That is the note of docs/topology_optimizer/metrics.md ("the AC solver counts this slightly differently than the DC solver. This is a bug, not a feature"): the same topology has two switching distances, the DC one is a repertoire descriptor (me_descriptors can bin on it) and the AC one is what the brief should quote, since it is closer to the operations of Exercise 3; and the unsplit topology has no AC value at all, because the AC metrics are only computed for k_best_topos candidates, the unsplit grid among them only by accident (the complex grid's cell 0).

    switching_distances.py
    """DC against AC switching distance for the validated topologies of a baseline run (Chapter 35, Exercise 4).

The DC value is ``extra_scores.switching_distance`` of ``res.json`` (``get_switching_distance`` in
``dc_solver/jax/aggregate_results.py``: the precomputed ``reassignment_distance`` of each applied branch action,
summed). The AC value is ``extra_scores.switching_distance`` of ``ac_metrics.json`` (``extract_switching_distance``
in ``optimizer/ac/scoring_functions.py``: the number of branch and injection reassignments of the realized
topology). ``python switching_distances.py`` prints the pairs of both baselines and describes the plot.
"""

import json
import sys
from pathlib import Path

import matplotlib
import pandas as pd

matplotlib.use('Agg')
import matplotlib.pyplot as plt  # noqa: E402

BASELINE = Path(__file__).resolve().parent / 'baseline'


def pairs(run_dir):
    """One row per ``topology_*`` folder: actions, DC and AC switching distance, DC and AC overload energy."""
    run_dir = Path(run_dir)
    res = json.loads((run_dir / 'res.json').read_text(encoding='utf-8'))
    by_actions = {tuple(t['actions']): t['metrics']['extra_scores'] for t in res['best_topos']}
    rows = []
    for path in sorted(run_dir.glob('topology_*/ac_metrics.json')):
        ac = json.loads(path.read_text(encoding='utf-8'))
        actions = tuple(ac['dc_info']['actions'])
        dc_scores = by_actions.get(actions, ac['dc_info']['metrics']['extra_scores'])
        rows.append(
            {
                'run': run_dir.name,
                'topology': path.parent.name,
                'actions': list(actions),
                'dc_switching_distance': dc_scores.get('switching_distance'),
                'ac_switching_distance': ac['extra_scores'].get('switching_distance'),
                'dc_overload_energy_n_1': dc_scores['overload_energy_n_1'],
                'ac_overload_energy_n_1': ac['extra_scores']['overload_energy_n_1'],
            }
        )
    return pd.DataFrame(rows)


def all_pairs(root=BASELINE):
    """The pairs of every run under ``baseline/<grid>/run_*``."""
    frames = [pairs(run_dir).assign(grid=run_dir.parent.name) for run_dir in sorted(root.glob('*/run_*'))]
    return pd.concat(frames, ignore_index=True)


def plot(table, ax=None):
    """Scatter of AC against DC switching distance with the diagonal; returns the axes."""
    ax = ax or plt.figure(figsize=(4, 4)).add_subplot()
    for grid, part in table.groupby('grid'):
        ax.scatter(part['dc_switching_distance'], part['ac_switching_distance'], label=grid)
    top = max(table['dc_switching_distance'].max(), table['ac_switching_distance'].max(), 1)
    ax.plot([0, top], [0, top], 'k--', linewidth=0.8, label='equal')
    ax.set_xlabel('DC switching distance (reassignment_distance of the actions)')
    ax.set_ylabel('AC switching distance (reassignments of the realized topology)')
    ax.legend()
    return ax


def main():
    """Print the table and the facts the figure would show."""
    table = all_pairs(Path(sys.argv[1]) if len(sys.argv) > 1 else BASELINE)
    pd.set_option('display.width', 200)
    print(table.to_string(index=False))
    diff = table['ac_switching_distance'] - table['dc_switching_distance']
    print(
        f'\n{len(table)} topologies; AC minus DC switching distance: min {diff.min()}, max {diff.max()}, '
        f'equal in {(diff == 0).sum()} of them'
    )
    plot(table)
    print('figure: one point per topology, DC on x, AC on y, with the diagonal for reference')


if __name__ == '__main__':
    main()

    Exercise 5¶

    In the DC model the AC grid does not see the HVDC link as a branch: the converter at bus \(i\) takes \(P\) out of the AC grid and the converter at bus \(j\) puts \(P\) back (losses neglected), so the link is a pair of injections, \(-P\) at \(i\) and \(+P\) at \(j\), and the AC branch flows are \(f = \mathrm{PTDF}\,(p - P e_i + P e_j)\). The PTDF is linear in the injections, so a setpoint change \(\Delta P\) changes the flows by

    \[ \Delta f = \mathrm{PTDF}\,(-\Delta P\, e_i + \Delta P\, e_j) = \Delta P\,(\mathrm{PTDF}_{\cdot,j} - \mathrm{PTDF}_{\cdot,i}), \]

    which is the chapter's \(\Delta P\,(\mathrm{PTDF}_{\cdot,i} - \mathrm{PTDF}_{\cdot,j})\) with the opposite convention for the direction of the link (positive setpoint from \(j\) to \(i\)). If \(i\) is the slack, its column is zero and the sensitivity is \(\Delta P\,\mathrm{PTDF}_{\cdot,j}\): the setpoint then moves power between the slack and \(j\), which is consistent, because the slack absorbs the balance. hvdc_sensitivity.check re-solves a six-bus meshed grid with the two injections changed by \(\Delta P = 0.37\) and compares with the column: the largest difference over all 30 ordered pairs is \(1.5 \times 10^{-16}\); the column of a link 2 → 5 is [0.3753, 0.5899, -0.4101, -0.2735, -0.488, 0.512, 0.1366, -0.2146] MW per MW, and the net flow leaving bus 2 changes by exactly −1 MW per MW of setpoint (Kirchhoff at the converter bus). The column is the same object as a PSDF column of Chapter 17 with the branch-side term left out: a PST is a loop-flow source on its own branch, an HVDC link an injection pair with no AC branch in between.

    Where it would live in ToOp: ToOp already treats controllable PSTs as "injections that are angles", NodalInjectionInformation (dc_solver/jax/types.py) with controllable_pst_indices (nodes whose injection the optimizer may vary), pst_tap_values and starting_tap_idx, written into the nodal injection tensor by write_pst_taps_to_nodal_injections (dc_solver/jax/pst.py) and optimized by nodal_inj_optim.py; the N-0 flows are then recomputed as \(\mathrm{PTDF}\cdot p\) by update_n0_for_pst_taps. An HVDC setpoint fits the same slot with two nodes instead of one: an hvdc_from_node, hvdc_to_node pair with a setpoint range (HVDCRange in interfaces/stored_action_set.py, which network_data.py still writes as hvdc_ranges=[]), the setpoint carried as traced data next to pst_tap_idx in the genotype, and the column \(\mathrm{PTDF}_{\cdot,j} - \mathrm{PTDF}_{\cdot,i}\) never stored, because it is read off the PTDF of the current topology at run time, after the BSDF updates, exactly as the PST path does. The preprocessing side would gather the converter stations the PowSyBl backend already collects in _get_injections (dc_solver/preprocess/powsybl/powsybl_backend.py) and their pmax, which is the project 7 plan of the chapter.

    hvdc_sensitivity.py
    """The DC sensitivity of every branch flow to an HVDC setpoint change, checked against a re-solve (Chapter 35, Ex. 5).

An HVDC link between buses i and j carrying P from i to j is, for the DC power flow of the AC grid, a withdrawal
of P at i and an injection of P at j. Raising the setpoint by dP therefore changes the nodal injections by
dp = -dP e_i + dP e_j and every branch flow by PTDF dp = dP (PTDF[:, j] - PTDF[:, i]); with the opposite
convention for the link's direction the sign flips. ``python hvdc_sensitivity.py`` prints the check.
"""

import numpy as np


def ptdf_matrix(fr, to, b, n_bus, slack=0):
    """PTDF (branch x bus) with a zero slack column."""
    a = np.zeros((len(fr), n_bus))
    a[np.arange(len(fr)), fr] = 1.0
    a[np.arange(len(fr)), to] = -1.0
    bf = a * np.asarray(b)[:, None]
    keep = np.arange(n_bus) != slack
    ptdf = np.zeros_like(a)
    ptdf[:, keep] = np.linalg.solve((a.T @ bf)[np.ix_(keep, keep)], bf[:, keep].T).T
    return ptdf


def six_bus():
    """A meshed six-bus grid: a ring with two chords, unit-ish susceptances, and a load pattern."""
    fr = np.array([0, 1, 2, 3, 4, 5, 0, 1])
    to = np.array([1, 2, 3, 4, 5, 0, 3, 4])
    b = np.array([2.0, 1.5, 1.0, 2.5, 1.0, 1.2, 0.8, 1.7])
    p = np.array([1.5, -0.4, -0.6, 0.0, -0.3, -0.2])
    return fr, to, b, p


def hvdc_column(ptdf, i, j):
    """Sensitivity of every branch flow to +1 MW of setpoint on a link that takes power out at i and in at j."""
    return ptdf[:, j] - ptdf[:, i]


def flows_with_setpoint(ptdf, p, i, j, setpoint):
    """Branch flows when the link moves ``setpoint`` MW from bus i to bus j (the AC grid sees two injections)."""
    dp = np.zeros_like(p)
    dp[i] -= setpoint
    dp[j] += setpoint
    return ptdf @ (p + dp)


def check(fr, to, b, p, i, j, delta=0.37):
    """Largest difference between the re-solved flow change and delta times the HVDC column."""
    ptdf = ptdf_matrix(fr, to, b, len(p))
    base = ptdf @ p
    direct = flows_with_setpoint(ptdf, p, i, j, delta) - base
    predicted = delta * hvdc_column(ptdf, i, j)
    return float(np.abs(direct - predicted).max())


def main():
    """Check the identity for every pair of buses, including pairs that contain the slack."""
    fr, to, b, p = six_bus()
    n = len(p)
    worst = max(check(fr, to, b, p, i, j) for i in range(n) for j in range(n) if i != j)
    print(f'six-bus grid, every ordered pair (i, j): largest |re-solve - dP (PTDF_j - PTDF_i)| = {worst:.2e}')
    ptdf = ptdf_matrix(fr, to, b, n)
    col = hvdc_column(ptdf, 2, 5)
    print('link 2 -> 5, flow change per MW of setpoint on each branch:', np.round(col, 4))
    print('sum of |column| (MW of branch flow moved per MW of setpoint):', round(float(np.abs(col).sum()), 4))
    print(
        'link 0 -> 3 with bus 0 the slack: column equals PTDF[:, 3]:',
        bool(np.allclose(hvdc_column(ptdf, 0, 3), ptdf[:, 3])),
    )


if __name__ == '__main__':
    main()

    Exercise 6¶

    One possible plan, for project 1 (clean-room solver), sized for a team and a semester; any project needs the same seven headings.

    • Research question. Can the published papers alone (arXiv:2501.17529 for PTDF/LODF, the BSDF paper, the MODF paper arXiv:1606.07276) reproduce ToOp's sensitivity factors to \(10^{-9}\) relative on IEEE 57 and on the node-breaker example grid, and which choices did the papers leave unspecified (slack handling in the BSDF, sign of the phase-shift column, the three singularity thresholds, the diagonal of the LODF)?
    • Baseline. ToOp ba1874e: dc_solver/jax/{bsdf,lodf,multi_outages}.py through run_solver_symmetric with a pass-through aggregation (Chapter 19), and numpy_reference.py as a second oracle.
    • Metrics. Largest absolute and relative difference per matrix (PTDF, LODF columns, MODF for every pair of outages ToOp enumerates, BSDF-updated PTDF for every action of the action set); the count of "underspecified choices" found, each documented by a failing property test before the choice is made; coverage of the clean-room code.
    • Budget. Two grids (IEEE 57 from data/case57_data_powsybl, the node-breaker example after a fresh preprocessing), every single action and every single and double outage of each, which is exhaustive, so no sampling; the Hypothesis properties of Chapter 33 on random meshed grids with 200 examples each as the third leg.
    • Seeds and repetitions. The comparison is deterministic; the only randomness is in the Hypothesis strategies, run with three fixed seeds (derandomize plus seed=1, 2, 3) and reported with the shrunk counterexample when one is found.
    • Statistical test. None is needed for a deterministic comparison; the report states the maximum differences and the tolerance they are judged against (\(10^{-9}\) relative for double precision, justified as in Chapter 33, Exercise 5), and a difference above the tolerance is a finding, not a failure.
    • The figure. One panel per matrix: the distribution (log scale) of relative differences between the clean-room code and ToOp over all actions and outages of both grids, with the tolerance as a vertical line and the underspecified cases marked, plus a table of the choices the papers leave open and what ToOp does for each. The deliverables that follow are the property tests ToOp could adopt and the issues for the papers' authors.
