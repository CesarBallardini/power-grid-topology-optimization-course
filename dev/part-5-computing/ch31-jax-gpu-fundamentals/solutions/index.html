    Lab¶

    1. Port. n1_flows in n1_screen.py is the single-outage function: the LODF column \((\mathrm{PTDF}_{\cdot,f_b}-\mathrm{PTDF}_{\cdot,t_b})/(1-(\mathrm{PTDF}_{b,f_b}-\mathrm{PTDF}_{b,t_b}))\), the diagonal entry forced to \(-1\) with jnp.where, the post-contingency flows \(f^0 + \mathrm{LODF}_{\cdot,b} f^0_b\), and a boolean flag |denom| > 1e-11 in place of the ValueError the NumPy loop raises for a bridge. screen = jax.jit(jax.vmap(n1_flows, in_axes=(None, None, None, None, 0))) adds the outage axis. grid_data.branch_data pulls from_bus, to_bus, x and the injections out of pandapower through its MATPOWER converter (bus numbers consecutive from zero, lines and transformers both branches), and grid_data.numpy_ptdf/numpy_screen are the Chapter 17 loop. On IEEE 14 (20 branches, 1 bridge) and IEEE 118 (186 branches, 9 bridges) the JAX flows match the NumPy flows to 1e-9 on every non-bridge outage, the two PTDFs match to 1e-9, and the flags match the bridges the loop skipped (test_grid_data.py).
    2. Second batch axis. n1_batch.screen_injections = jax.jit(jax.vmap(screen, in_axes=(None, None, None, 0, None))): a vmap of the already jitted, already vmapped screening, with the batch on the injection argument only. random_injections splits one key into 100 subkeys and perturbs the base injection by 10 % Gaussian noise. One call on IEEE 118 returns flows of shape (100, 186, 186) in float64 and ok of shape (100, 186); the 9 bridges are flagged in every one of the 100 injections (900 False flags in all, since a bridge is a property of the topology, not of the injection); the largest post-contingency flow of a batch member ranges from 362.2 to 624.0 MW; the same key gives the same batch (True).

      timing_sweep.py
      """Compile time against steady-state time of the N-1 screening, per grid size and precision (Chapter 31, Lab 3).

Run as ``python timing_sweep.py`` for the four grids of the lab (a few minutes on a laptop CPU). Set
``JAX_PLATFORMS=cpu`` for the CPU, or leave JAX to pick the GPU when it has one (a JAX with the CUDA plugin). Two
more modes::

    python timing_sweep.py repeat 3   # one warm-up sweep, then the median of three sweeps
    python timing_sweep.py agree      # the same screening on the GPU and on the CPU, compared entry by entry
"""

import statistics
import sys
import time

import jax
import jax.numpy as jnp
import numpy as np
from grid_data import branch_data
from n1_screen import ptdf_matrix, screen

CASES = ('case118', 'case300', 'case1354pegase', 'case2869pegase')


def time_screen(ptdf, from_bus, to_bus, p, repeats: int = 10) -> tuple[float, float]:
    """Seconds of the first call (compilation included) and the median of the next ``repeats`` calls.

    Every call waits for its result with ``block_until_ready``; without that, JAX's asynchronous dispatch
    returns before the device has finished and the timer measures nothing. The cache is cleared first so that
    the first call always compiles, even when the same shapes were seen earlier in the process.
    """
    jax.clear_caches()
    outages = jnp.arange(ptdf.shape[0])
    start = time.perf_counter()
    jax.block_until_ready(screen(ptdf, from_bus, to_bus, p, outages))
    first = time.perf_counter() - start
    later = []
    for _ in range(repeats):
        start = time.perf_counter()
        jax.block_until_ready(screen(ptdf, from_bus, to_bus, p, outages))
        later.append(time.perf_counter() - start)
    return first, statistics.median(later)


def sweep(cases: tuple[str, ...] = CASES, repeats: int = 10) -> list[dict]:
    """One row per grid and precision: branch count, output size, first-call and steady-state seconds.

    The PTDF is built once in float64 and cast, so the float32 rows measure the screening itself in float32.
    """
    rows = []
    for case in cases:
        from_bus, to_bus, x, p = (jnp.array(v) for v in branch_data(case))
        ptdf64 = ptdf_matrix(from_bus, to_bus, x, len(p))
        for dtype in (jnp.float64, jnp.float32):
            ptdf, inj = ptdf64.astype(dtype), p.astype(dtype)
            first, steady = time_screen(ptdf, from_bus, to_bus, inj, repeats)
            n_branch = ptdf.shape[0]
            rows.append(
                {
                    'case': case,
                    'n_branch': n_branch,
                    'dtype': jnp.dtype(dtype).name,
                    'output_mb': n_branch * n_branch * jnp.dtype(dtype).itemsize / 1e6,
                    'first_s': first,
                    'steady_s': steady,
                }
            )
    return rows


def repeated_sweep(cases: tuple[str, ...] = CASES, repeats: int = 10, runs: int = 3) -> list[dict]:
    """``sweep`` once as a warm-up (backend start-up, file caches, GPU clocks), then ``runs`` times; the medians.

    Every run clears the compilation cache per row, so each ``first_s`` is a full compilation again.
    """
    sweep(cases, repeats)
    results = [sweep(cases, repeats) for _ in range(runs)]
    return [
        {**rows[0], **{k: statistics.median(r[k] for r in rows) for k in ('first_s', 'steady_s')}}
        for rows in zip(*results, strict=True)
    ]


def agreement(case: str) -> dict:
    """The screening of ``case`` on the default device (the GPU, if any) against the CPU, and float32 against float64.

    Each device builds its own PTDF and screens every outage. Flows are compared on the outages that both runs
    flag as valid; ``missed_bridges`` counts the bridges the float32 run does not flag (its denominator is
    rounding noise instead of zero, far above the ``1e-11`` threshold), whose flows look valid and are not.
    """
    data = branch_data(case)
    out = {'case': case, 'devices': (str(jax.devices()[0]), str(jax.devices('cpu')[0]))}
    runs = {}
    for name, device, dtype in (
        ('default64', jax.devices()[0], jnp.float64),
        ('cpu64', jax.devices('cpu')[0], jnp.float64),
        ('default32', jax.devices()[0], jnp.float32),
    ):
        with jax.default_device(device):
            from_bus, to_bus, x, p = (jax.device_put(jnp.array(v), device) for v in data)
            ptdf = ptdf_matrix(from_bus, to_bus, x, len(p)).astype(dtype)
            flows, ok = screen(ptdf, from_bus, to_bus, p.astype(dtype), jnp.arange(ptdf.shape[0]))
            runs[name] = (np.asarray(flows, dtype=np.float64), np.asarray(ok))
    for label, (a, b) in {
        'device_vs_cpu_float64': ('default64', 'cpu64'),
        'float32_vs_float64': ('default32', 'default64'),
    }.items():
        (fa, oka), (fb, okb) = runs[a], runs[b]
        both = oka & okb
        diff = np.abs(fa[both] - fb[both]).max()
        out[label] = {
            'max_abs_mw': float(diff),
            'max_rel': float(diff / np.abs(fb[both]).max()),
            'flags_equal': bool((oka == okb).all()),
            'missed_bridges': int((oka & ~okb).sum()),
            'missed_max_flow_mw': float(np.abs(fa[oka & ~okb]).max()) if (oka & ~okb).any() else None,
        }
    return out


def main() -> None:
    """Print the table the log-log plot is drawn from (time against number of branches, one line per dtype)."""
    mode = sys.argv[1] if len(sys.argv) > 1 else 'once'
    print('backend:', jax.default_backend(), '-', jax.devices()[0].device_kind, '- JAX', jax.__version__)
    if mode == 'agree':
        for case in CASES:
            print(agreement(case))
        return
    rows = repeated_sweep(runs=int(sys.argv[2])) if mode == 'repeat' else sweep()
    print(f'{"case":15s} {"branches":>8s} {"dtype":>8s} {"output MB":>10s} {"first [s]":>10s} {"steady [ms]":>11s}')
    for r in rows:
        print(
            f'{r["case"]:15s} {r["n_branch"]:8d} {r["dtype"]:>8s} {r["output_mb"]:10.1f} '
            f'{r["first_s"]:10.3f} {r["steady_s"] * 1e3:11.3f}'
        )


if __name__ == '__main__':
    main()

    4. Accidental recompilation. compile_count.counting wraps a function so that a Python counter runs on every Python-level call; under jit the Python body only runs while tracing, so the counter counts compilations. With the outage set as a Python tuple marked static (screen_static), every distinct tuple is a new cache key: on the four-bus grid, 4 calls with 4 distinct pairs give 4 traces, and in general ten different outage sets give ten compilations, even though all have the same length (the test checks that the count equals the number of distinct tuples, and that a second round of the same tuples adds none). With a fresh lambda passed as the static post argument (screen_then), 10 calls give 10 traces: every lambda expression evaluates to a new function object, and function objects hash by identity. The fixes: pass the outages as a jnp array, so only its shape and dtype matter (screen in the worked example), and define the post-processing function once at module level (worst_flow): 10 calls, 1 trace. The proof: after one warm-up call per shape, the fixed versions run inside with jax.no_tracing(): without error, while a call with a new outage length inside that block raises RuntimeError (test_compile_count.py). Build the index arrays before entering the block: creating an array is itself a dispatch that no_tracing flags the first time it sees that shape and dtype.

      compile_count.py (the static tuple)
      def _screen_static(ptdf, from_bus, to_bus, p, outages: tuple):
    """The outage set as a Python tuple marked static: one compilation per distinct tuple."""
    return jax.vmap(n1_flows, in_axes=(None, None, None, None, 0))(ptdf, from_bus, to_bus, p, jnp.array(outages))


screen_static_counted, static_traces = counting(_screen_static)
screen_static = jax.jit(screen_static_counted, static_argnums=4)
      compile_count.py (the fresh lambda and the fix)
      def _screen_then(ptdf, from_bus, to_bus, p, outages, post):
    """Screen, then apply a post-processing function passed as a static argument."""
    flows, ok = screen(ptdf, from_bus, to_bus, p, outages)
    return post(flows), ok


screen_then_counted, then_traces = counting(_screen_then)
screen_then = jax.jit(screen_then_counted, static_argnames='post')


def worst_flow(flows):
    """Largest absolute flow per outage. Defined once at module level: one function object, one compilation."""
    return jnp.abs(flows).max(axis=1)

    Exercise 2¶

    Eagerly, clip_negative_python works ([0, 2, 0, 5] for x = [-1, 2, -3, 5]). Under jit the if asks bool() of a tracer and raises TracerBoolConversionError (a ConcretizationTypeError): while tracing, JAX knows the shape and dtype of x.sum() > 0 but not its value, so it cannot pick a branch. Both fixes give the same result under jit:

    control_flow.py (the three versions)
    def clip_negative_python(x):
    """Python ``if`` on a traced value: fine eagerly, TracerBoolConversionError under jit."""
    if x.sum() > 0:
        return jnp.maximum(x, 0.0)
    return x


def clip_negative_where(x):
    """Both branches are computed on every call; ``where`` picks per element."""
    return jnp.where(x.sum() > 0, jnp.maximum(x, 0.0), x)


def clip_negative_cond(x):
    """One branch is executed at run time (outside vmap); the predicate is a scalar."""
    return lax.cond(x.sum() > 0, lambda v: jnp.maximum(v, 0.0), lambda v: v, x)

    jnp.where evaluates both branches on every call and selects per element; lax.cond compiles both but executes only the taken one (its predicate must be a scalar). It matters when a branch is expensive (you pay for both with where), when the untaken branch produces inf or NaN that leak through gradients, and when a branch has side effects (jax.debug.print). The gradient shows it: for safe_sqrt_where(x) = where(x > 0, sqrt(x), 0), jax.grad at \(x=-1\) is nan, because the derivative of sqrt is evaluated at \(-1\) and \(0 \times \text{NaN}\) is NaN; with lax.cond it is 0.0. Under vmap, however, cond is lowered to a select_n over both branches (jax.make_jaxpr(jax.vmap(clip_negative_cond)) contains select_n), because different batch members may take different branches: inside a vmapped, jitted solver like ToOp's, cond buys nothing over where, and the code uses jnp.where and masks throughout.

    Exercise 3¶

    pad_indices([[0, 1, 2], [3], [1, 3]], sentinel=4) gives [[0, 1, 2], [3, 4, 4], [1, 3, 4]] and x.at[idx].get(mode="fill", fill_value=0.0) on x = [10, 20, 30, 40] returns [[10, 20, 30], [40, 0, 0], [20, 40, 0]]: index 4 is out of bounds, so the slot reads the fill value and the row sums [60, 40, 60] are the sums of the real members. With sentinel=-1 the gather returns [[10, 20, 30], [40, 40, 40], [20, 40, 40]] and the row sums become [60, 120, 100]: JAX normalizes negative indices like NumPy does, so -1 is the last element, in bounds, and every padding slot silently adds x[-1]. Nothing fails; the numbers are just wrong. That is why production code pads with a large positive sentinel (ToOp's int_max(), Chapter 32): it is out of bounds for every array the code will ever index, so mode="fill" drops it, and if it ever shows up in a result it is an obviously impossible index rather than a plausible one. The same reasoning says why an int64 sentinel stored in an int32 array is dangerous: it wraps to -1, which is this exercise's bad case.

    control_flow.py (padding and gathering)
    def pad_indices(groups: list[list[int]], sentinel: int) -> jnp.ndarray:
    """Variable-length index lists as one rectangular int array, unused slots filled with ``sentinel``."""
    width = max(len(g) for g in groups)
    return jnp.array([list(g) + [sentinel] * (width - len(g)) for g in groups])


def gather_fill(x, idx):
    """Gather with out-of-bounds slots replaced by 0.0; valid sentinels are >= len(x), never negative."""
    return x.at[idx].get(mode='fill', fill_value=0.0)

    Exercise 4¶

    lodf_precision.lodf_matrix computes the whole LODF matrix at once, in the dtype of the PTDF it is given; the study builds the PTDF of IEEE 118 in float64 and casts it to float32 for the second run, so the difference measures what the LODF formula itself does to float32 round-off (a float32 PTDF solve would add its own error of order \(10^{-6}\) relative on top). IEEE 118 has 9 bridges, with \(|1-(\mathrm{PTDF}_{b,f_b}-\mathrm{PTDF}_{b,t_b})| < 10^{-11}\); their columns are infinite in both precisions and are excluded. Over the 177 other outages the largest float32 error of a column has median \(1.1 \times 10^{-7}\) and maximum \(5.5 \times 10^{-7}\), and it grows as the denominator shrinks: median \(2.5 \times 10^{-7}\) for \(|\text{denom}| < 0.2\) against \(5.7 \times 10^{-8}\) for \(|\text{denom}| \ge 0.5\), with a correlation of \(-0.79\) between \(\log_{10}\) error and \(\log_{10} |\text{denom}|\). The five smallest denominators among non-bridges are the outages of branches 114–115 (0.053), 70–71 (0.059), 108–109 (0.069), 4–5 (0.072) and 65–68 (0.080), with errors between \(1.6 \times 10^{-7}\) and \(5.1 \times 10^{-7}\). On the plot (error against \(|\text{denom}|\), both axes logarithmic) the cloud slopes down to the right: these are the near-bridges. A branch whose outage leaves only a weak parallel path has \(\mathrm{PTDF}_{b,f_b}-\mathrm{PTDF}_{b,t_b}\) close to 1, so the division by \(1-(\cdot)\) amplifies the round-off of the numerator by \(1/|\text{denom}|\): a condition number, in the sense of Chapter 4, that is set by the topology, not by the solver. In float64 the same amplification acts on \(10^{-16}\) and is harmless; in float32 it eats a quarter of the seven significant digits for the worst outages here, and all of them on a grid with a denominator of \(10^{-4}\). This is why ToOp forces float64 even on GPUs that pay for it.

    lodf_precision.py
    """LODF of IEEE 118 in float32 and float64: which outages lose accuracy, and why (Chapter 31, Exercise 4)."""

import jax.numpy as jnp
import numpy as np
from grid_data import branch_data
from n1_screen import ptdf_matrix


def lodf_matrix(ptdf, from_bus, to_bus):
    """LODF (monitored branch x outaged branch) in the dtype of ``ptdf``, plus the LODF denominators.

    LODF[a, b] = (PTDF[a, f_b] - PTDF[a, t_b]) / (1 - (PTDF[b, f_b] - PTDF[b, t_b])), LODF[b, b] = -1.
    Bridges have a zero denominator and an infinite column; the caller masks them with ``abs(denom) > 1e-11``.
    """
    col = ptdf[:, from_bus] - ptdf[:, to_bus]  # (n_branch, n_outage)
    denom = 1.0 - jnp.diagonal(col)
    lodf = col / denom[None, :]
    eye = jnp.eye(ptdf.shape[0], dtype=bool)
    return jnp.where(eye, -1.0, lodf), denom


def precision_study(case: str = 'case118') -> dict:
    """Per outage: |denominator| and the largest |LODF32 - LODF64| in its column (bridges excluded)."""
    from_bus, to_bus, x, p = (jnp.array(v) for v in branch_data(case))
    ptdf64 = ptdf_matrix(from_bus, to_bus, x, len(p))
    lodf64, denom = lodf_matrix(ptdf64, from_bus, to_bus)
    lodf32, _ = lodf_matrix(ptdf64.astype(jnp.float32), from_bus, to_bus)
    ok = np.abs(np.asarray(denom)) > 1e-11
    error = np.full(len(ok), np.nan)  # bridge columns are infinite in both precisions: no error to compare
    error[ok] = np.abs(np.asarray(lodf32, dtype=np.float64)[:, ok] - np.asarray(lodf64)[:, ok]).max(axis=0)
    return {
        'from_bus': np.asarray(from_bus),
        'to_bus': np.asarray(to_bus),
        'abs_denom': np.abs(np.asarray(denom)),
        'error': error,
        'ok': ok,
    }


def main() -> None:
    """Print the bridges, the five outages with the smallest denominators and the error trend."""
    study = precision_study()
    ok, denom, error = study['ok'], study['abs_denom'], study['error']
    print(f'{int((~ok).sum())} bridges (|1 - (PTDF_b,fb - PTDF_b,tb)| < 1e-11), excluded from the comparison')
    order = np.argsort(denom + np.where(ok, 0.0, np.inf))[:5]
    print('smallest denominators among non-bridges:')
    for b in order:
        print(
            f'  outage {b:3d} (bus {study["from_bus"][b] + 1:3d}-{study["to_bus"][b] + 1:3d}): '
            f'|denom| = {denom[b]:.4f}, max |LODF32 - LODF64| = {error[b]:.2e}'
        )
    print(f'float32 error over all non-bridge outages: median {np.median(error[ok]):.1e}, max {error[ok].max():.1e}')
    small, large = np.median(error[ok][denom[ok] < 0.2]), np.median(error[ok][denom[ok] >= 0.5])
    print(f'median error, |denom| < 0.2: {small:.1e}; |denom| >= 0.5: {large:.1e}')
    rho = np.corrcoef(np.log10(denom[ok]), np.log10(error[ok]))[0, 1]
    print(f'correlation of log10 error with log10 |denom|: {rho:.2f}')

    Exercise 5¶

    Both versions start from MATPOWER's makePTDF and the base-case flows \(f^0 = H P\). The loop takes one outage at a time: one PTDF column difference, one scalar denominator, one rank-one update. The vectorized version forms all column differences at once, col = H(:, f) - H(:, t) (an \(n_l \times n_l\) matrix whose column \(k\) belongs to outage \(k\)), divides every column by its own denominator with broadcasting, sets the diagonal to \(-1\), blanks the bridge columns, and builds every post-contingency flow vector in one expression F = f0' + L' .* f0. On IEEE 118 (Octave 11.3, MATPOWER 8.1, CPU) the two give identical matrices (largest difference exactly 0, the same 9 bridge rows) and take 3.2–3.7 ms for the loop against 0.4–0.5 ms vectorized, a factor of about 8. The vectorized rewrite is what jax.vmap does for you: it takes the one-outage function and adds the batch axis mechanically, with no hand-written broadcasting. jit adds what no array language can: it compiles the whole batched program into one fused XLA executable, so the intermediate \(n_l \times n_l\) matrices (col, L, L') need not all be materialized, Python and interpreter overhead disappear from the steady state, and the same program runs unchanged on a GPU. One finding on the way: makeLODF(mpc, H, true) (bridge masking) of MATPOWER 8.1 stops with br(197): out of bound 186 inside find_bridges on case118, so the file masks the bridges itself.

    n1_loop_vs_vec.m
    function [F_loop, F_vec, t_loop, t_vec] = n1_loop_vs_vec(casename)
  % N-1 flows of every single branch outage of a MATPOWER case, computed twice: a for loop over the
  % outages and one vectorized matrix expression, each timed (Chapter 31, Exercise 5).
  % Row k of F is the flow vector after the outage of branch k; bridge rows are NaN in both versions.
  define_constants;
  mpc = ext2int(loadcase(casename));
  H  = makePTDF(mpc);                                   % PTDF, slack = reference bus
  Pbus = real(makeSbus(mpc.baseMVA, mpc.bus, mpc.gen)) * mpc.baseMVA;   % net injections, MW
  f0 = H * Pbus;                                        % base-case flows
  f = mpc.branch(:, F_BUS);
  t = mpc.branch(:, T_BUS);
  nl = size(mpc.branch, 1);

  tic;
  F_loop = nan(nl, nl);
  for k = 1:nl                                          % one outage at a time, as a Python loop would
    col = H(:, f(k)) - H(:, t(k));
    denom = 1 - col(k);
    if abs(denom) < 1e-11
      continue;                                         % bridge: islands the grid, row stays NaN
    end
    lodf = col / denom;
    lodf(k) = -1;
    F_loop(k, :) = (f0 + lodf * f0(k))';
  end
  t_loop = toc;

  tic;
  col = H(:, f) - H(:, t);                              % column k: PTDF difference of outage k, all at once
  denom = 1 - diag(col)';                               % 1 - (H(k, f_k) - H(k, t_k)) as a row vector
  L = col ./ denom;                                     % broadcasting divides each column by its denominator
  L(1:nl + 1:end) = -1;                                 % the outaged branch loses its flow
  L(:, abs(denom) < 1e-11) = NaN;                       % bridges (makeLODF(mpc, H, true) fails on case118 in 8.1)
  F_vec = f0' + L' .* f0;                               % F(k, a) = f0(a) + L(a, k) f0(k), by broadcasting
  t_vec = toc;
end

    shape_check.py (the annotated function)
    # ruff reads the shape strings as forward references and reports F722; ToOp ignores that rule repository-wide
@jaxtyped(typechecker=beartype)
def n1_flows_checked(
    ptdf: Float[Array, ' n_branch n_bus'],  # noqa: F722
    from_bus: Int[Array, ' n_branch'],  # noqa: F722
    to_bus: Int[Array, ' n_branch'],  # noqa: F722
    p: Float[Array, ' n_bus'],  # noqa: F722
    outage: Int[Array, ''],  # noqa: F722
) -> tuple[Float[Array, ' n_branch'], Bool[Array, '']]:  # noqa: F722
    """The worked example's ``n1_flows`` with every shape named; the same name must mean the same size."""
    f0 = ptdf @ p
    col = ptdf[:, from_bus[outage]] - ptdf[:, to_bus[outage]]
    denom = 1.0 - col[outage]
    lodf = jnp.where(jnp.arange(ptdf.shape[0]) == outage, -1.0, col / denom)
    return f0 + lodf * f0[outage], jnp.abs(denom) > 1e-11

    A valid call gives the worked example's first row, [0, 100, -25, 25, 75] with the flag True. Called with a PTDF of 4 columns and an injection vector of 5 entries, the function raises jaxtyping.TypeCheckError (a TypeError subclass) whose message names the mismatch: "The problem arose whilst typechecking parameter 'p'. Actual value: f64[5]. Expected type: Float[Array, 'n_bus']", followed by the shapes of every argument and the current bindings n_branch=5, n_bus=4 (set by ptdf, which was checked first). Eagerly it happens at call time, before any arithmetic. Under jit it happens while tracing: the tracers that stand for the arguments carry concrete shapes and dtypes, which is all jaxtyping checks, so the error appears on the first call for a given set of shapes, with the same message, and never at execution. The flip side is that a cached call does not run the Python body at all, so it is not checked again, which is fine, since its shapes are by definition the ones that passed. This is also why ToOp can leave ENABLE_BEARTYPE on in its test configuration at no run-time cost: the checks run once per compilation, not once per batch. The course environment does not ship jaxtyping and beartype; test_shape_check.py skips there and passes with ToOp's interpreter.
