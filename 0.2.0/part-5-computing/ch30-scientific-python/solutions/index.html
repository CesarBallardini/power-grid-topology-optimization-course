    Chapter 30 – Solutions¶

    Solutions of the Lab and the Exercises of Chapter 30. Try each task before reading its solution. The code is in the chapter's src folder: two_libraries.py (the worked example), incidence.py, sparse_vs_dense.py, ieee14_flows.py, case57_ac_dc.py and loading_query.py, each with a test_*.py next to it. Every script prints the numbers quoted below when run from the src folder (python incidence.py, and so on). The numbers come from the course environment (pandapower 3.5, pypowsybl 1.16, NumPy 2.4, SciPy 1.18, Python 3.14 on Windows); the Polars parts were run with ToOp's environment (Polars 1.42, ToOp commit ba1874e), which is the one that has Polars. Lab steps 1–2 and Exercise 6 quote the output of commands run in the ToOp container, given with each solution.

    Lab¶

    1. Environment. The code lives in /app, a bind mount of your checkout on the host, so a file edited on Windows is the file the container imports, with no copy and no rebuild (the six packages/* are installed editable). The environment lives in /opt/venv, on the named volume toop-venv, because the Dockerfile sets UV_PROJECT_ENVIRONMENT=/opt/venv (and puts /opt/venv/bin first on PATH). They are kept apart because a Linux virtual environment under /app/.venv would collide with a .venv created natively on Windows and would push thousands of small files across the WSL2 file-system bridge on every import; on the named volume it stays on the Linux side and survives docker compose down (docker compose down -v deletes it, which is the documented repair when it gets into a bad state). The facts are from the course fork's docker/README.md ("Why the virtualenv is not in the repository folder") and docker/Dockerfile, and the container confirms them (see Exercise 6): /opt/venv/bin/python is a symbolic link to the image's /usr/local/bin/python3.11, so the environment holds the packages and borrows the interpreter, and the environment's 3.0 GB (du -sh /opt/venv) never touch the Windows side.

    2. Tests. The threshold is in the [report] section of .coveragerc: fail_under = 90, with show_missing = true (the report lists the uncovered line numbers) and sort = cover (the report is sorted by coverage, so the least-covered modules are at the top of the table and the three you are asked for are its first three rows). The plain run is uv run pytest packages/interfaces_pkg/tests -q; the CI-style run adds --cov=packages/interfaces_pkg/src --cov-config=.coveragerc, with UV_PROJECT=packages/interfaces_pkg so that uv run resolves the package's own project.

Every array argument and return value carries a jaxtyping type with a shape string: Float[np.ndarray, " n_branches n_nodes"] for the PTDF, Int[np.ndarray, " n_branches"] for from_node and to_node, Bool[np.ndarray, " n_branches_at_node"] for the busbar assignment, and tuples of them for multiple return values. The names in the strings (n_branches, branches_from_a, ...) are documentation here; the same strings are checked at run time in the JAX code when beartype is on (Chapter 31, Exercise 6).
      • Docstrings. NumPy style: a summary line, then Parameters, Returns and Raises sections with name : type headers, not the Google style of this course's code.
      • Fancy indexing. Integer arrays pick columns in ptdf[:, i] - ptdf[:, j] (calc_lodf) and rows in ptdf[branch_to_a, :] (_compute_ptdf_difference); boolean masks select branches in branches_locally[~assignment & branch_direction_locally] (get_bsdf_branch_indices); an in-place fancy-indexed update nom[branch_from_a] += suscept_from_a in _compute_bsdf_vector; a slice of a boolean vector topo_vect[topo_vect_index : topo_vect_index + len(branches_at_node)] in extract_bsdf_data.
      • Broadcasting. ptdf[:, node_from_a] - ptdf_bus_a subtracts a (n_branches, 1) column from a (n_branches, k) block (_compute_pedf_terms); suscept_from_a * pedf_from multiplies a (k,) vector into every row of a (n_branches, k) matrix; np.outer(bsdf, ptdf_diff) is the rank-one PTDF update of Chapter 18; and n_0_flows + lodf * n_0_flows[branch_to_outage] is the LODF update of Chapter 17.
      • Errors. _validate_assignment raises AssertionError when a busbar gets no branch (and get_bsdf_branch_indices and extract_bsdf_data use bare assert statements for length checks); _compute_bsdf_denominator raises ValueError when \(|\text{denom}| < 10^{-5}\) (the split would island the grid) and calc_lodf raises ValueError when \(|\text{denom}| < 10^{-11}\) (a bridge). Only the second is caught: contingency_analysis wraps calc_lodf in try/except ValueError, stores a zero row and False in the success array, and goes on, which is exactly the "flag instead of exception" habit the JAX version must adopt (Chapter 31). A BSDF failure in compute_bus_splits propagates and stops run_solver.

      case57_ac_dc.py
      """AC and DC from-end flows of pandapower's case57 side by side, in pandas and Polars, with a histogram (Lab 4)."""

import matplotlib.pyplot as plt
import numpy as np
import pandas as pd
from two_libraries import pandapower_case57


def side_by_side() -> pd.DataFrame:
    """One row per line of case57: AC flow, DC flow and their difference, all in MW at the from end."""
    _, ac_p, dc_p = pandapower_case57()
    df = pd.DataFrame({'ac_p_from_mw': ac_p, 'dc_p_from_mw': dc_p})
    df['difference_mw'] = df['ac_p_from_mw'] - df['dc_p_from_mw']
    return df


def to_polars(df: pd.DataFrame):
    """The same table as a Polars frame (Polars is in ToOp's environment, not in the course one)."""
    import polars as pl

    return pl.from_pandas(df.reset_index(names='line'))


def histogram(df: pd.DataFrame, bins: int = 20) -> plt.Figure:
    """Histogram of the AC - DC difference of the from-end flows."""
    fig, ax = plt.subplots()
    ax.hist(df['difference_mw'], bins=bins)
    ax.set_xlabel('AC - DC from-end flow [MW]')
    ax.set_ylabel('lines')
    ax.set_title('case57: where the DC approximation is off')
    return fig


def main() -> None:
    """Print the summary of the difference and the histogram counts that the figure shows."""
    df = side_by_side()
    print(df.round(2).head())
    print(df['difference_mw'].describe().round(2))
    worst = df['difference_mw'].abs().idxmax()
    print(f'largest gap: line {worst}, AC {df.ac_p_from_mw[worst]:.1f} MW, DC {df.dc_p_from_mw[worst]:.1f} MW')
    counts, edges = np.histogram(df['difference_mw'], bins=10)
    print('histogram counts:', counts.tolist())
    print('bin edges [MW]:', np.round(edges, 1).tolist())
    try:
        print(to_polars(df).head(3))
    except ImportError:
        print("Polars is not installed in this environment; run the script with ToOp's interpreter to see it")


if __name__ == '__main__':
    main()

    Exercise 1¶

    Two fancy-indexed assignments build the whole matrix: a[rows, from_bus] = 1.0 and a[rows, to_bus] = -1.0, with rows = np.arange(n_branch). Each row has exactly one \(+1\) and one \(-1\), so it sums to zero, and \(A^\top A\) is the Laplacian (Chapter 2): for the four-bus, five-branch grid of the Chapter 31 worked example its diagonal is the degree sequence \((2, 3, 3, 2)\). The test is parametrized over a three-bus path, a triangle and that four-bus grid, and also checks the Laplacian of the triangle and the two ValueErrors. uv run pytest docs/part-5-computing/ch30-scientific-python/src/test_incidence.py reports 5 passed (three parametrized cases plus two tests).

    incidence.py
    """Branch-bus incidence matrix of a graph as a type-annotated NumPy function (Chapter 30, Exercise 1)."""

import numpy as np


def incidence_matrix(from_bus: np.ndarray, to_bus: np.ndarray, n_bus: int) -> np.ndarray:
    """Dense incidence matrix with one row per branch: +1 at the from bus, -1 at the to bus.

    Args:
        from_bus: Integer array with the from bus of every branch.
        to_bus: Integer array with the to bus of every branch, same length.
        n_bus: Number of buses, which fixes the number of columns.

    Returns:
        Float array of shape (n_branch, n_bus). Every row sums to zero because each branch leaves one bus and
        enters another; A.T @ A is the graph Laplacian (Chapter 2).

    Raises:
        ValueError: If the two bus arrays differ in length or a branch connects a bus to itself.
    """
    from_bus, to_bus = np.asarray(from_bus, dtype=int), np.asarray(to_bus, dtype=int)
    if from_bus.shape != to_bus.shape:
        raise ValueError('from_bus and to_bus must have the same length')
    if np.any(from_bus == to_bus):
        raise ValueError('a branch cannot start and end at the same bus')
    rows = np.arange(len(from_bus))
    a = np.zeros((len(from_bus), n_bus))
    a[rows, from_bus] = 1.0
    a[rows, to_bus] = -1.0  # fancy indexing: one assignment per branch, no Python loop
    return a


def main() -> None:
    """The four-bus, five-branch grid of the Chapter 31 worked example and its Laplacian."""
    a = incidence_matrix([0, 0, 1, 1, 2], [1, 2, 2, 3, 3], 4)
    print(a)
    print('row sums:', a.sum(axis=1))
    print('Laplacian A.T @ A:')
    print(a.T @ a)


if __name__ == '__main__':
    main()
    test_incidence.py
    import numpy as np
import pytest
from incidence import incidence_matrix

GRAPHS = [
    ([0, 1], [1, 2], 3),  # a path of three buses
    ([0, 1, 2], [1, 2, 0], 3),  # a triangle
    ([0, 0, 1, 1, 2], [1, 2, 2, 3, 3], 4),  # the four-bus grid of Chapter 31
]


@pytest.mark.parametrize(('from_bus', 'to_bus', 'n_bus'), GRAPHS)
def test_every_row_sums_to_zero(from_bus, to_bus, n_bus):
    a = incidence_matrix(from_bus, to_bus, n_bus)
    assert a.shape == (len(from_bus), n_bus)
    np.testing.assert_array_equal(a.sum(axis=1), np.zeros(len(from_bus)))


def test_triangle_laplacian():
    a = incidence_matrix([0, 1, 2], [1, 2, 0], 3)
    np.testing.assert_array_equal(a.T @ a, [[2, -1, -1], [-1, 2, -1], [-1, -1, 2]])


def test_bad_input_raises():
    with pytest.raises(ValueError, match='same length'):
        incidence_matrix([0, 1], [1], 2)
    with pytest.raises(ValueError, match='same bus'):
        incidence_matrix([0, 1], [1, 1], 2)

    Exercise 2¶

    random_symmetric(n) draws scipy.sparse.random(n, n, density=0.02), symmetrizes it with \(M + M^\top\) and adds \(2n I\) so the matrix is strictly diagonally dominant, hence never singular; at \(n = 200\) it has 1 766 nonzeros of 40 000. The two solvers agree to \(3.9 \times 10^{-18}\). timings() takes the best of three timeit runs of spsolve and of np.linalg.solve(a.toarray(), b) (the conversion is part of the dense route). On the machine that wrote this (CPU timings, two runs, so you see how much they move):

    \(n\) spsolve [ms] dense solve [ms] dense / sparse
    200 1.0–1.1 36–66 34–67
    400 5.7–6.5 162–192 25–33
    800 33–36 362–533 10–16
    1600 276–296 542–988 2.0–3.3
    3200 2 077–2 093 935–1 076 0.5

    On log-log axes the dense curve is a line of slope about 3 (\(n^3\) flops) once \(n\) is large enough for the BLAS overhead to be negligible, while the sparse curve is steeper, close to slope 3 as well between 800 and 3200: the LU factors of a random sparse matrix fill in almost completely, so the sparse solver ends up doing dense work with sparse bookkeeping and the dense solver overtakes it near \(n \approx 2000\)–3000. Grid matrices are different: a power system's \(B\) matrix is close to planar, and a fill-reducing ordering keeps its factors sparse, which is why SciPy sparse (and ToOp's preprocessing) stay far ahead on real grids. The lesson of the plot is that "sparse" is a property of the pattern, not of the count of zeros.

    sparse_vs_dense.py
    """Sparse against dense linear solves on random symmetric matrices, timed with timeit (Chapter 30, Exercise 2)."""

import timeit
from functools import partial

import numpy as np
import scipy.sparse as sp
from scipy.sparse.linalg import spsolve


def random_symmetric(n: int, density: float = 0.02, seed: int = 0) -> sp.csc_matrix:
    """Random sparse symmetric matrix, made strictly diagonally dominant so that it is never singular.

    Args:
        n: Matrix size.
        density: Fraction of nonzero entries of the random part before symmetrization.
        seed: Seed of the NumPy generator.

    Returns:
        The matrix M + M.T + 2 n I in CSC format, the format spsolve prefers.
    """
    rng = np.random.default_rng(seed)
    m = sp.random(n, n, density=density, format='csc', random_state=rng)
    return (m + m.T + 2 * n * sp.identity(n, format='csc')).tocsc()


def dense_solve(a: sp.csc_matrix, b: np.ndarray) -> np.ndarray:
    """Solve a x = b with the dense LAPACK solver of NumPy, conversion to a dense array included."""
    return np.linalg.solve(a.toarray(), b)


def solve_both(a: sp.csc_matrix, b: np.ndarray) -> tuple[np.ndarray, np.ndarray]:
    """Solve a x = b with the sparse LU of spsolve and with the dense solver."""
    return spsolve(a, b), dense_solve(a, b)


def timings(sizes: tuple[int, ...], density: float = 0.02, repeat: int = 3) -> list[tuple[int, float, float]]:
    """Best-of-repeat run time in seconds of spsolve and of numpy.linalg.solve for each size.

    The dense timing includes the conversion to a dense array, since that is what the dense route costs when the
    matrix arrives sparse. The sparse run time grows roughly with the fill-in of the LU factors; the dense one
    grows as n**3.
    """
    out = []
    for n in sizes:
        a = random_symmetric(n, density)
        b = np.ones(n)
        t_sparse = min(timeit.repeat(partial(spsolve, a, b), number=1, repeat=repeat))
        t_dense = min(timeit.repeat(partial(dense_solve, a, b), number=1, repeat=repeat))
        out.append((n, t_sparse, t_dense))
    return out


def main() -> None:
    """Check the two solutions agree at n = 200, then print the timing table for the plot."""
    a = random_symmetric(200)
    x_sparse, x_dense = solve_both(a, np.ones(200))
    print(
        f'n = 200: {a.nnz} nonzeros of {200 * 200}, max |x_sparse - x_dense| = {np.abs(x_sparse - x_dense).max():.2e}'
    )
    print(f'{"n":>6s} {"spsolve [ms]":>14s} {"dense solve [ms]":>18s} {"dense/sparse":>13s}')
    for n, t_sparse, t_dense in timings((200, 400, 800, 1600, 3200)):
        print(f'{n:6d} {1e3 * t_sparse:14.2f} {1e3 * t_dense:18.2f} {t_dense / t_sparse:13.1f}')


if __name__ == '__main__':
    main()

    ieee14_flows.py
    """AC and DC active line flows of pypowsybl's IEEE 14 case, sorted by magnitude (Chapter 30, Exercise 3)."""

import matplotlib.pyplot as plt
import pandas as pd
import pypowsybl as pypo


def _converged(results) -> None:
    """Stop if the load flow of the main synchronous component did not converge."""
    if results[0].status != pypo.loadflow.ComponentStatus.CONVERGED:
        raise RuntimeError(f'load flow did not converge: {results[0].status}')


def line_flows() -> pd.DataFrame:
    """Active power at the from end of every line after an AC and after a DC load flow.

    Returns:
        Frame indexed by line id with the columns ``p1_ac`` and ``p1_dc`` (MW), sorted by decreasing |p1_ac|.
        The DC run overwrites the same ``p1`` column of ``get_lines()``, which is why the AC values are copied
        first.
    """
    n = pypo.network.create_ieee14()
    _converged(pypo.loadflow.run_ac(n))
    p1_ac = n.get_lines()['p1'].copy()
    _converged(pypo.loadflow.run_dc(n))
    p1_dc = n.get_lines()['p1']
    df = pd.DataFrame({'p1_ac': p1_ac, 'p1_dc': p1_dc})
    return df.reindex(df['p1_ac'].abs().sort_values(ascending=False).index)


def bar_chart(df: pd.DataFrame) -> plt.Figure:
    """Two bar series side by side, one line per group of bars, in the order of the frame."""
    fig, ax = plt.subplots(figsize=(9, 4))
    pos = range(len(df))
    ax.bar([p - 0.2 for p in pos], df['p1_ac'], width=0.4, label='AC')
    ax.bar([p + 0.2 for p in pos], df['p1_dc'], width=0.4, label='DC')
    ax.set_xticks(list(pos), df.index, rotation=90)

    Exercise 4¶

    res_line_case57() joins from_bus and to_bus from net.line onto net.res_line (63 lines). The pandas version is eager, two statements: a boolean mask with the median, then groupby('from_bus')['loading_percent'].mean(). The Polars version is one lazy expression chain: pl.from_pandas(...).lazy().filter(pl.col('loading_percent') > pl.col('loading_percent').median()).group_by('from_bus').agg(pl.col('loading_percent').mean()).sort('from_bus').collect(). Nothing is computed until collect(), the median is an expression inside the filter rather than a value computed beforehand, and group_by does not sort its output (pandas does), hence the explicit sort. Results: the median loading is 0.17 %, 31 of the 63 lines are above it, they leave from 23 distinct buses, and the five highest means are from bus 7 (1.78 %), 0 (1.13 %), 1 (0.99 %), 6 (0.84 %) and 13 (0.67 %). The Polars frame holds the same 23 rows to floating-point precision (test_loading_query.py, run with ToOp's interpreter; the from_bus column comes back as u32, pandas keeps it as int64). The percentages are tiny because the MATPOWER case57 ships no line ratings and pandapower fills max_i_ka with a very large value: the exercise is about the query, and the ranking is what the numbers mean.

    loading_query.py
    """The same query on pandapower's case57 line results in pandas and in Polars (Chapter 30, Exercise 4).

Keep the lines whose loading is above the median, then average the loading per from bus.
"""

from __future__ import annotations

from typing import TYPE_CHECKING

import pandapower as pp
import pandapower.networks as pn

if TYPE_CHECKING:
    import pandas as pd


def res_line_case57() -> pd.DataFrame:
    """``net.res_line`` of case57 after an AC power flow, with the ``from_bus`` of every line joined in."""
    net = pn.case57()
    pp.runpp(net)
    return net.res_line.join(net.line[['from_bus', 'to_bus']])


def pandas_query(df: pd.DataFrame) -> pd.Series:
    """Mean loading per from bus of the lines above the median loading, eager pandas style."""
    above = df[df['loading_percent'] > df['loading_percent'].median()]
    return above.groupby('from_bus')['loading_percent'].mean()


def polars_query(df: pd.DataFrame):
    """The same result with a Polars LazyFrame: nothing runs until ``collect()``."""
    import polars as pl

    query = (
        pl.from_pandas(df.reset_index(names='line'))
        .lazy()
        .filter(pl.col('loading_percent') > pl.col('loading_percent').median())
        .group_by('from_bus')
        .agg(pl.col('loading_percent').mean())
        .sort('from_bus')
    )
    return query.collect()


def main() -> None:
    """Print the median, the pandas result and, when Polars is installed, the Polars result."""
    df = res_line_case57()
    print(f'{len(df)} lines, median loading {df["loading_percent"].median():.2f} %')
    result = pandas_query(df)
    print(f'{len(result)} from buses with at least one line above the median; the five most loaded:')
    print(result.sort_values(ascending=False).head().round(2).to_string())
    try:
        print(polars_query(df).head())
    except ImportError:
        print("Polars is not installed in this environment; run the script with ToOp's interpreter to see it")


if __name__ == '__main__':
    main()

    Exercise 6¶

    Run in the course image toop-course:cpu (built from the course fork's docker/Dockerfile) with ToOp commit ba1874e mounted at /app. Both commands print /opt/venv/bin/python: the Dockerfile sets UV_PROJECT_ENVIRONMENT=/opt/venv and puts /opt/venv/bin first on PATH, so the shell's python and uv run's interpreter are the same file. which -a python also lists /usr/local/bin/python, the image's own interpreter, which is what a stock python:3.11-slim image without that PATH change would answer; and readlink -f /opt/venv/bin/python gives /usr/local/bin/python3.11: the environment is a folder of packages around the image's interpreter.

    To see what a restart keeps without touching the compose project, the same experiment can be made with two docker run --rm containers (each one deleted on exit, as docker compose down deletes its container) that share a named volume at /opt/venv, as the compose file mounts toop-venv. From Git Bash, in the ToOp checkout:

    docker volume create try-venv
for i in 1 2; do
  MSYS_NO_PATHCONV=1 docker run --rm -v "$(pwd -W):/app:ro" -v try-venv:/opt/venv -w /app toop-course:cpu \
    bash -c 'ls /opt/venv/marker.txt /root/marker.txt; date > /opt/venv/marker.txt; date > /root/marker.txt'
done
docker volume rm try-venv

    The first container starts with an empty volume, which Docker seeds from the image's /opt/venv; its entrypoint's uv sync rebuilds the seven editable ToOp packages (Prepared 7 packages in 29.85s) and ls finds neither marker. The second container prints Checked 312 packages in 60ms (the rebuilt packages are on the volume) and finds /opt/venv/marker.txt but not /root/marker.txt. So, after docker compose down and docker compose up -d:

    • /opt/venv survives: it is the named volume toop-venv, which down leaves alone (only down -v removes volumes). The entrypoint still runs uv sync at every start, but it finds nothing to do (60 ms above).
    • /app survives for a different reason: it is a bind mount, the files live on the host.
    • Everything written elsewhere in the container's file system (a pip install into the image's Python, a file under /root or /tmp, an apt-get install) lives in the container's writable layer, which down deletes together with the container; up -d starts a fresh container from the image, so that state is gone.

    The rule: state you want to keep goes in a volume or a bind mount, and the image is rebuilt, never patched in place.
